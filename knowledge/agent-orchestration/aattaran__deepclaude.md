# aattaran/deepclaude — Distilled Knowledge

## What it is

`deepclaude` is a local proxy and CLI wrapper that intercepts Claude Code CLI's API traffic and redirects it to cheaper backends — DeepSeek V4 Pro, OpenRouter, or Fireworks AI — while preserving Claude Code's full autonomous-agent UX (file editing, bash execution, multi-step tool loops) [README.md:1-19]. It exists purely to solve a cost problem: Claude Code's usage caps and per-token cost with native Anthropic models are high, and swapping the underlying model (e.g. to DeepSeek V4 Pro, cited at 96.4% on LiveCodeBench) can be up to ~17x cheaper for comparable agentic coding performance, without the user's workflow changing at all. This is not an agent framework or memory system itself — it's a narrow, single-purpose "protocol adapter + cost-shifting proxy" sitting in front of one. Distributed as platform-specific launcher scripts (`deepclaude.sh` for macOS/Linux, `deepclaude.ps1` for Windows) plus a small Node.js proxy (`proxy/model-proxy.js`, `proxy/start-proxy.js`).

## Architecture

**Three layers**: (1) CLI Wrappers (`deepclaude.sh`/`.ps1`) detect available API keys and export the environment variables Claude Code uses to locate its "backend" — critically, `ANTHROPIC_BASE_URL` is pointed at the local proxy (`localhost:3200`) rather than `api.anthropic.com`, and `ANTHROPIC_DEFAULT_SONNET_MODEL`/`OPUS_MODEL`/`HAIKU_MODEL` are set so Claude Code *believes* it's still talking to real Claude models even though the proxy will translate underneath. (2) Local Proxy (`model-proxy.js`, orchestrated by `start-proxy.js`) — a Node.js `http.Server` that intercepts `POST /v1/messages`, remaps model names, sanitizes protocol differences, and forwards to the actual configured backend. (3) Control Plane — a `/_proxy/*` HTTP API on the same port allowing live backend switching and cost inspection without restarting the Claude Code process.

**Model remapping (`MODEL_REMAP`)**: a static table translating Claude model IDs (e.g. `claude-opus-4-7`, `claude-sonnet-4-6`) into the selected backend's equivalent model IDs (e.g. `deepseek-v4-pro`, `deepseek/deepseek-v4-pro` for the OpenRouter-routed variant) — this is what lets Claude Code's hardcoded model-name expectations survive a full backend swap underneath.

**`UsageNormalizer` (SSE transform stream)**: DeepSeek and OpenRouter sometimes omit the `usage` field on early Server-Sent-Event chunks; Claude Code expects `usage.input_tokens` to always be present on `message_start`/`message_delta` events and will crash if it's missing. `UsageNormalizer` buffers SSE chunks, parses the JSON payloads, and injects a zeroed `usage` object whenever the upstream provider left it out — a defensive protocol-shim pattern for bridging providers with slightly different streaming-response completeness guarantees under a nominally shared wire format (both claim "Anthropic-compatible," neither is byte-identical).

**Thinking-block sanitization**: Claude Code's message history can contain `thinking`-type content blocks (native Anthropic extended-reasoning output). Many non-Anthropic providers reject requests containing them outright. Two sanitization levels: `stripAllThinkingBlocks` removes every thinking block unconditionally; `stripUnsignedThinkingBlocks` removes only those lacking a cryptographic signature — the signed/unsigned distinction matters specifically when transitioning *back* to Anthropic mid-session after having used a non-Anthropic backend, since Anthropic's own API may reject unsigned reasoning blocks it didn't itself produce, while it's fine with properly-signed ones from its own prior turns.

**Split authentication for remote-control mode**: Claude Code's `remote-control` feature (browser-based UI) uses two separate channels that normally share one Anthropic credential — a WebSocket "Bridge" channel (`wss://bridge.claudeusercontent.com`, for UI sync/command relay, authenticated via Anthropic OAuth) and an HTTP "Model API" channel (normally `api.anthropic.com`, for actual inference). Setting a DeepSeek/OpenRouter key globally breaks the Bridge channel outright (that key is invalid there), rendering the remote UI unusable. `deepclaude` resolves this by only intercepting the model-specific HTTP path (`/v1/messages`) via `ANTHROPIC_BASE_URL`, while explicitly `unset`-ing `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY` before launching the CLI so the Bridge channel falls back to standard OAuth — a deliberate credential-domain split rather than a single override, because the two channels have genuinely incompatible auth requirements under a naive single-key setup.

## Key patterns & techniques

**Agent self-reconfiguration via slash commands that call a local control API**: Claude Code supports Markdown-file-defined slash commands under `~/.claude/commands/`. `deepclaude` ships `deepseek.md`, `anthropic.md`, `openrouter.md` command files, each instructing the agent to run a `curl -X POST http://127.0.0.1:3200/_proxy/mode -d "backend=<name>"` against the proxy's control plane. The flow: user types `/deepseek` → Claude Code reads the command file's Markdown instructions → the *agent itself* executes the curl command as one of its own tool calls → the proxy's `switchMode()` mutates internal state → all subsequent `/v1/messages` calls in the same session route to the new backend, with zero process restart. This is a genuinely reusable technique for any agent framework: give the agent a documented, narrow HTTP control surface and a slash-command/skill file that tells it how to call it, and the agent can reconfigure its own execution substrate mid-session as an ordinary tool-use step, no special "reconfiguration mode" needed in the host framework.

**Localhost-only control plane as the security boundary**: `/_proxy/*` endpoints check `req.socket.remoteAddress` and only permit `127.0.0.1`/`::1`; anything else gets rejected outright. The stated rationale for why the *agent* is allowed to hit this endpoint without extra credentials is that the agent process itself runs locally, so it inherently satisfies the loopback check — the security model is "only same-machine processes can reconfigure," not "only authenticated callers can reconfigure." This is a reasonable boundary for a single-user local dev tool but would need real auth if the proxy were ever exposed beyond localhost.

**Live cost tracking via a static pricing table + real-time comparison**: `PRICING_PER_M` holds per-million-token rates for each backend plus Anthropic's own rates. On every response, `recordUsage` tallies actual tokens; `getCostSummary()` computes both the "actual USD spent" (using the active backend's rate) and the "Anthropic-equivalent USD" (same token counts at Anthropic's rate), with `savings = AnthropicEq − Actual` exposed via `GET /_proxy/cost`. This is a simple but effective pattern for any cost-sensitive proxy/router: track usage against the counterfactual price, not just the actual price, so savings are visible in real time rather than requiring after-the-fact billing reconciliation.

**Legacy vs. Standalone proxy startup modes**: `start-proxy.js` branches on whether `targetUrl`/`apiKey` positional args (or `CHEAPCLAUDE_TARGET_URL`/`CHEAPCLAUDE_API_KEY` env vars) are present. **Legacy Mode** (used internally by the `.sh`/`.ps1` wrappers) only wires up backends whose API keys are actually present in the environment, and is meant for short-lived, single-session proxy instances — it logs only the resolved port to stdout so the calling shell script can capture it programmatically. **Standalone Mode** (for users running the proxy as a persistent background service) wires up *all* known backend definitions even when a key is missing (setting it to `null`), enabling a "live toggle" UX where you can add a key or switch modes later via the control API without restarting the process; it defaults to DeepSeek as the fallback target and substitutes the literal string `"unused"` for a missing API key specifically to avoid the proxy engine crashing on an undefined credential during initialization.

## Practical how-tos

**Basic backend switching from the CLI**: `deepclaude --backend ds` (DeepSeek), `--backend or` (OpenRouter), `--backend fw` (Fireworks), `--backend anthropic` (standard native behavior) — the wrapper script's `resolve_backend` function maps the flag to the right upstream URL/key and exports the corresponding `ANTHROPIC_DEFAULT_*_MODEL` and `ANTHROPIC_BASE_URL` variables before spawning the `claude` process.

**Diagnostics before committing to a session**: `deepclaude --status` checks which API keys are present and whether a proxy instance is already running; `deepclaude --cost` prints a static pricing comparison table across providers; `deepclaude --benchmark` sends a minimal request to each configured provider to latency-test them — useful for picking a backend before starting real work rather than discovering a slow/misconfigured provider mid-task.

**Remote-control mode**: `deepclaude --remote` (optionally combined with `--backend ds`) starts the proxy in a background process, explicitly unsets Anthropic auth env vars so the Bridge channel falls back to OAuth, and registers a `trap` on shell `EXIT` to kill the background proxy process when the session ends — a cleanup pattern worth copying for any wrapper script that spawns a background helper process tied to a foreground session's lifetime.

**Querying/switching a running proxy manually**: `curl -s http://127.0.0.1:3200/_proxy/cost` for savings; `curl -sX POST http://127.0.0.1:3200/_proxy/mode -d "backend=openrouter"` to switch; `curl -s http://127.0.0.1:3200/_proxy/status` to confirm — useful for scripting or debugging outside the slash-command flow.

## Gotchas & caveats

- **A DeepSeek/OpenRouter/Fireworks key set as `ANTHROPIC_AUTH_TOKEN` globally will silently break `remote-control` mode's Bridge channel** — this is exactly the split-authentication problem the tool exists to solve; if you're building something similar and only intercept the HTTP model channel while leaving a global auth token in place, expect the WebSocket bridge to fail with an invalid-credential error that looks unrelated to your proxy at first glance.
- **Missing `usage` fields on early SSE chunks from non-Anthropic providers will crash Claude Code outright** if not normalized — this is presented as an observed, not hypothetical, failure mode, meaning any similarly-built Anthropic-API-compatible proxy needs to proactively backfill zeroed usage objects rather than assuming "compatible" providers match the wire format exactly.
- **Thinking-block compatibility is asymmetric and session-state-dependent**: `hadNonAnthropicSession` is set to `true` the moment any non-Anthropic backend is used, and this flag changes behavior later — if the user switches back to `anthropic` mode afterward, the proxy must specifically strip *unsigned* thinking blocks (not all of them) to avoid the native Anthropic API rejecting reasoning content it doesn't recognize as its own. A naive "always strip all thinking blocks" or "never strip" policy would break one direction or the other.
- **Legacy Mode only wires up backends with keys actually present**, while Standalone Mode wires up all of them (nulling missing keys) — code or scripts assuming a uniform "all defined backends are always in the registry" behavior across both modes would be wrong; the registry's completeness depends on which mode started the proxy.
- **The control plane's security model is loopback-only, not authenticated** — acceptable for a local single-user dev tool where "same machine" implies "trusted," but this pattern doesn't generalize to any deployment where the proxy process and its caller aren't guaranteed to be the same trust domain.
