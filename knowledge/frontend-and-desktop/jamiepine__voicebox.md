# Voicebox (jamiepine/voicebox) — DeepWiki Knowledge Distillation

## What it is

Voicebox is a local-first, open-source voice synthesis studio positioned as a private alternative to cloud services like ElevenLabs and WisprFlow. It clones voices from short reference audio samples, generates speech in 23 languages across 7 different TTS engines, and composes multi-voice narratives via a DAW-like timeline editor ("Stories"). All model weights, voice data, and inference stay on the user's hardware — no cloud round-trip for generation. It ships as a desktop app (macOS/Windows/Linux via Tauri) and Docker deployment, plus a browser-only web variant. Version at time of wiki generation was 0.5.0.

## Architecture

**Three-tier hybrid stack**: a Rust Tauri shell (native OS integration, sidecar process management, hardware audio I/O) hosts a React frontend (Zustand stores + TanStack Query) that talks over local REST/SSE to a bundled Python FastAPI backend (the actual ML inference server, packaged via PyInstaller and run as a Tauri "sidecar" binary on port 17493). The monorepo (Bun workspaces) splits into `app` (React UI), `tauri` (Rust shell), `backend` (Python/FastAPI/PyTorch/MLX/SQLAlchemy), `landing` (Next.js marketing site), and `web` (browser-only Vite build using standard Web Audio APIs instead of the native Rust audio subsystem).

**Sidecar lifecycle is a full state machine, not just process spawn**. On startup, Tauri's `main.rs` first checks whether port 17493 is already occupied (supports "keep running" mode and dev workflows) using platform-specific discovery — PowerShell `Get-NetTCPConnection` + `tasklist` on Windows (replacing an older `netstat`-based approach that broke on systems with corrupted DLLs), plain socket connection attempts on Unix. If occupied, it verifies the occupant is actually a Voicebox server via a strict `/health` check (`status=="healthy"`, `model_loaded`/`gpu_available` present as booleans) rather than trusting the port. If free, it spawns the bundled binary. A **version fast-path** lets the Rust side confirm compatibility without paying ML-library import cost: calling the binary with `--version` imports only `__version__` and exits immediately, sidestepping the 30+ second cost of importing `torch`/`transformers`. A background **parent watchdog thread** in the Python process polls the Tauri PID (`OpenProcess`+`GetExitCodeProcess`/`STILL_ACTIVE` on Windows, `os.kill(pid, 0)` on Unix) and self-terminates if the parent dies — unless a `.keep-running` sentinel file exists in the data directory, which is how "keep server running after window close" is implemented without a discrete IPC message.

**Native audio bypasses browser limitations via a Rust subsystem**: system-audio loopback capture (for building voice-clone samples from other apps' output) uses `ScreenCaptureKit`/`SCStream` on macOS (12.3+ required), WASAPI loopback (`AUDCLNT_STREAMFLAGS_LOOPBACK`) on a dedicated COM thread on Windows, and PulseAudio/PipeWire `.monitor` source discovery via `pactl` + `PULSE_SOURCE` env var on Linux — capabilities a standard browser `getUserMedia` call cannot provide. Multi-device output routing lets one generated clip play to several physical devices simultaneously (e.g. monitor speakers + a virtual-cable input for streaming software): `cpal` opens a separate parallel `Stream` per target device, all consuming from the same decoded (`symphonia`) sample buffer, each independently resampled to its device's native rate.

**Backend TTS engines are pluggable via a `TTSBackend` protocol + declarative registry**: every engine (Qwen3-TTS on MLX/PyTorch, Chatterbox, Chatterbox Turbo, LuxTTS/ZipVoice, Kokoro, HumeAI TADA) implements `load_model`, `create_voice_prompt`, `combine_voice_prompts`, `generate`, `unload_model`. A `ModelConfig` dataclass carries each engine's HF repo ID, size, supported languages, and capability flags (`needs_trim`, `supports_instruct`); the route/service layer dispatches purely off this registry, so adding an engine requires zero changes to request-handling code — only a new backend file plus a registry entry.

**Generation runs through a single-slot serial queue, not a thread pool**, specifically to avoid GPU VRAM contention/OOM from concurrent model loads: `backend/services/task_queue.py` holds a global `asyncio.Queue` and one `_generation_worker` that pulls `GenerationJob`s one at a time. Long text is chunked (`generate_chunked`, default threshold 800 chars) at sentence/clause boundaries via regex that specifically avoids splitting inside abbreviations ("Mr.") or paralinguistic tags ("[laugh]"), synthesized chunk-by-chunk, then rejoined with a linear 50ms crossfade to avoid audible clicks at chunk boundaries.

## Key patterns & techniques

**Offline/air-gapped inference via monkey-patched HF constants with refcounting**: modern `transformers` (4.57+) performs unconditional network calls during tokenizer load (e.g. Mistral-regex metadata checks) that throw when offline. `force_offline_if_cached()` is a context manager that mutates `huggingface_hub.constants.HF_HUB_OFFLINE` and `transformers.utils.hub._is_offline_mode` directly (because those libraries cache the corresponding env vars at import time, so setting the env var alone doesn't help post-import) — guarded by a global lock + refcount so concurrent inference tasks don't prematurely re-enable network access while another task is still relying on offline mode. A separate patch wraps the specific problematic tokenizer method to swallow the metadata-lookup exception and return the tokenizer unchanged.

**PyInstaller-frozen ML binaries require an explicit "Phase 0" compatibility audit before writing any backend code** (formalized as a documented checklist and an internal `.agents/skills/add-tts-engine` automation skill): check whether the target library calls `inspect.getsource()` (breaks in frozen binaries because `.py` source isn't present — common in libraries decorated with `@typechecked` or using `torch.jit.script`); check for `Path(__file__).parent`-relative data loading (breaks because frozen binaries extract to a temp `_MEIPASS` dir, not the original package location); check for hardcoded gated HuggingFace repos; avoid `torchaudio.load` (pulls in `torchcodec` in newer versions) in favor of `soundfile.read()`/`librosa`; and if a dependency needs only a small piece of a heavy package (e.g. TADA needs just the `Snake1d` layer from `descript-audio-codec`), write a **shim module** that vendors only that piece rather than bundling the whole dependency tree — see `backend/utils/dac_shim.py`.

**GPU runtime libraries are split-binary-packaged and versioned independently from the app**: CUDA (~2.43GB) and ROCm (~2.1GB) are too large to bundle in the base installer, so each is built as a PyInstaller `--onedir` output and split post-build into a "Server Core" archive (executable + non-vendor deps, redownloaded on every app update) and a "Vendor Libs" archive (cuBLAS/cuDNN/HIP/Tensile etc., versioned by toolkit e.g. `cu128-v1`/`rocm7.2-v1`, only redownloaded when that identifier changes). Both extract into the same directory to preserve the relative paths the dynamic linker expects. Download integrity is checked against a `.sha256` fetched alongside the archive; installed state is tracked in a `cuda-libs.json`/`rocm-libs.json` manifest; an `asyncio.Lock` prevents a manual UI-triggered download from racing an auto-update check. After install, the app must be restarted — Tauri detects the presence of the GPU binary variant and launches that instead of the default CPU sidecar.

**Idempotent, Alembic-free SQLite migrations that survive PyInstaller bundling**: rather than a migration tool, `backend/database/migrations.py` runs `run_migrations(engine)` on every startup, inspects current schema via `sqlalchemy.inspect`, and for each table checks column existence before mutating. Because SQLite has no `DROP COLUMN`, structural changes (e.g. removing a column or changing constraints) recreate the table under a `_new` suffix, copy data across (including on-the-fly transforms — one migration converts `story_items` from position-based ordering to absolute `start_time_ms` by computing offsets from generation durations), then drop-and-rename. Storage paths are kept relative to the data directory (`to_storage_path`/`resolve_storage_path`) specifically so a user can move their entire `data/` folder to a new machine or drive without breaking any file references — including a legacy-path-normalization pass for records that pre-date this convention.

**Sample-accurate multi-track audio playback uses the Web Audio API graph, not `<audio>` tags**: the Stories timeline editor's `useStoryPlayback` hook tracks `playbackStartContextTime` (an `AudioContext.currentTime` snapshot) and `playbackStartStoryTime` (story position in ms) to compute exact per-clip start offsets, schedules each clip as an `AudioBufferSourceNode` → per-clip `GainNode` → master `GainNode` → destination, and preloads/caches decoded `AudioBuffer`s keyed by generation/version ID for zero-latency starts across overlapping tracks. Trimming is a visual illusion, not a data cut: `ClipWaveform` renders the full original waveform and uses CSS `translateX` inside an `overflow:hidden` container to visually hide the trimmed regions, while playback scheduling separately respects `trim_start_ms`/`trim_end_ms`.

**A silent looping audio stream keeps the OS audio session "hot"**: Tauri apps run inside a WKWebView (macOS) which, like many embedded webviews, can let the audio hardware go dormant under OS power management or WebKit idle heuristics, adding latency/glitches to the next real playback. `AudioKeepAlive` generates a minimal 1-second silent WAV (raw RIFF header, zero PCM samples) via `buildSilentWavUrl` and loops it continuously at volume 1.0 specifically to prevent this dormancy — a narrow, documented workaround for a specific embedded-webview quirk rather than a general audio-engine feature.

**Voice profiles are typed by generation strategy, and the type gates engine compatibility**: `cloned` (zero-shot from user-supplied reference `samples`, works with Qwen/LuxTTS/Chatterbox/TADA), `preset` (fixed built-in speakers tied to a specific engine binary via `preset_engine`+`preset_voice_id`, e.g. Kokoro's voice library or Qwen CustomVoice's named speakers), and `designed` (text-description-driven, noted as still in development). The frontend's `EngineModelSelector` filters selectable engines per profile using an `isProfileCompatibleWithEngine` check so a Kokoro preset voice can never be pointed at the Qwen engine, since preset voices are baked into a specific model's embedding space.

## Practical how-tos

- **Add a new TTS engine**: implement the `TTSBackend` protocol in `backend/backends/your_engine_backend.py` (must handle device-specific dtype casting, return audio array + sample rate); register a `ModelConfig` entry and add the engine to the `TTS_ENGINES` map in `backend/backends/__init__.py`; wire the frontend in five places (`types.ts` union, `languages.ts` support map, `EngineModelSelector.tsx` options, `useGenerationForm.ts` Zod schema, `ModelManagement.tsx` download-size metadata); then update `build_binary.py` with any needed `--hidden-import`/`--collect-all`/`--copy-metadata` flags for PyInstaller. Do Phase 0 dependency research (see above) before writing any code — it's explicitly gated in the internal automation skill.
- **Debug a "server not responding" issue after an update**: check whether the version fast-path (`--version` flag) returns cleanly; if the port is occupied by a stale process, the platform-specific discovery logic (PowerShell on Windows, socket probe on Unix) plus the strict `/health` schema check should correctly refuse to treat an unrelated service on the same port as the Voicebox server.
- **Diagnose GPU acceleration not activating after download**: confirm `VOICEBOX_BACKEND_VARIANT` is set to `cuda`/`rocm` at startup and that both the Server Core and Vendor Libs archives extracted into the same directory (a partial/mismatched extraction breaks the dynamic linker's relative-path assumptions).
- **Move a Voicebox installation to a new machine**: copy the entire `data/` directory (contains `voicebox.db` plus all audio files) — paths are stored relative to that directory specifically to make this safe.
- **Package a dependency that needs `torch.jit.script` or `inspect.getsource()`**: don't bundle it directly for the frozen binary; either patch out the JIT/getsource usage or write a narrow shim (pattern: `backend/utils/dac_shim.py`) that reimplements only the needed layer/function without pulling in the full package.

## Gotchas & caveats

- `torchaudio.load` should be avoided in new backend code — newer versions require `torchcodec`, an extra dependency the project has chosen not to carry; use `soundfile.read()` or `librosa` instead.
- The offline-mode patch mutates library-internal constants rather than relying on environment variables alone, because `huggingface_hub`/`transformers` cache those env vars at import time — setting `HF_HUB_OFFLINE=1` after the process has already imported those modules will not reliably take effect without the explicit constant mutation.
- SQLite's lack of `DROP COLUMN` means every destructive schema migration is a full table-recreate-and-copy, which is more failure-prone than a simple `ALTER TABLE`; the migration framework carries explicit column-existence checks precisely because it runs on every single startup, not just once.
- GPU backend downloads are large (multi-GB) and split into two independently-versioned archives — a partial or interrupted download of either half can leave the install in a state where the manifest (`cuda-libs.json`) claims a version that doesn't match what's actually on disk.
- The parent watchdog's Unix path additionally ignores `SIGHUP` when the watchdog is disabled, specifically so the sidecar can survive its session leader exiting — a naive `os.kill(pid,0)`-only implementation without this SIGHUP handling would kill "keep running" mode when the terminal/session closes.
- Voice-clone reference samples are capped at 50MB and must include a matching transcript (`reference_text`); a `preset` voice profile can never be repointed at an incompatible engine because preset speaker IDs are meaningless outside their originating model's embedding space.
